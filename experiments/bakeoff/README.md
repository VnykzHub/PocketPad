# PocketPad engine bake-off (2026-10-23)

**Goal:** decide custom vs PlayCanvas vs Babylon.js from measured results on this
machine. This file is the binding contract for the three contender folders and
the shared asset/runner folder. Do not change it without updating every folder.

**Decision rule (from `references/decision we need.md`):** adopt PlayCanvas or
Babylon.js unless the custom renderer meets the frame budget (p95 14 ms at
1920×1080) on this scene and both alternatives miss it, or both alternatives
have a blocking gap that cannot be fixed with a plugin, or either alternative's
cold boot gzip breaks the 5 MiB boot budget.

**Not a claim until measured.** Every number in `results/` must name the
contender, Chrome version, backend, date and 1920×1080. No software-renderer
numbers, no invented values.

| Folder | Owner | Contents |

any other contender's files. Do not commit unless asked.

## Shared scene (identical in all three)

World: a 3×3 grid of 64 m cells, origin `(-96, 0, -96)`; cell `(cx, cy)` covers
`[origin.x + cx*64, origin.x + (cx+1)*64) × [origin.z + cy*64, ...)`.

- Ground: 192×192 m at y=0, with a 12 m ring road at ±32 m.
- Buildings: **14** boxes in the centre cell, footprint 8×8 m, heights 12–28 m,
  positions from `assets/layout.json`; each building belongs to a cell.
- Car: one 1,250 kg body with 4 wheels at `(0, 0.5, 32)`, driven on a fixed
  scripted path (20 m/s) for the measured run; keyboard drive is optional.
- Pedestrians: **50** skinned instances walking a loop in the south cells at
  1.2 m/s, each with the shared walk animation; each belongs to a cell.
- Light/sky: one directional light with shadows enabled and a sky background.
- Streaming: only objects whose cell is the camera's cell or a neighbour are
  active; objects in other cells are deactivated. The camera follows the car
  through the 3×3 grid over the 60 s run. Record activations/deactivations.
- Backend: prefer WebGPU; fall back to WebGL2 if WebGPU is unavailable. Record
  which backend ran. Do not silently run software rendering.

## Shared assets (`assets/`)

| File | Contract |
|---|---|
| `ground.glb` | 192×192 plane, y=0, one material |
| `building.glb` | 8×8×height box; one node; UVs; facade material |
| `car.glb` | body + 4 wheel nodes named `wheel-fl`, `wheel-fr`, `wheel-rl`, `wheel-rr`; metres |
| `ped.glb` | one skinned mesh, 2+ bones, walk animation clip named `walk`, duration 1.0 s, loops |
| `facade.png` | 256×256 generated texture, CC0 |
| `layout.json` | fields below |
| `LICENSES.csv` | one row per asset: file, source, author, licence, date, attribution |

`layout.json` fields (synthetic example values, all required):

```json
{
  "cellSizeMeters": 64,
  "origin": { "x": -96, "y": 0, "z": -96 },
  "buildings": [{ "cell": "0,0", "x": 0, "z": 0, "height": 16 }],
  "pedestrians": [{ "cell": "1,2", "x": 4, "z": 8, "waypoint": 0 }],
  "car": { "x": 0, "y": 0.5, "z": 32, "yaw": 0 },
  "cameraPath": [{ "x": 0, "z": 32 }, { "x": 0, "z": -32 }],
  "runSeconds": 60
}
```

Assets must be generated by us (CC0) or carry a clear licence in
`LICENSES.csv`. **Do not copy Mixamo, bitmoji, or any asset whose licence is
unclear.** A minimal generated skinned quad with a bone rotation is acceptable
for `ped.glb`; it must be skinned and animated, not a rigid box.

## Metrics interface

Every page sets, after load:

```js
window.__BAKEOFF__ = {
  ready: true,
  backend: "webgpu" | "webgl2" | "unknown",
  frameTimesMs: [/* measured frame intervals after warm-up */],
  drawCalls: 0,
  triangles: 0,
  instances: 0,
  firstFrameMs: 0,
  activations: 0,
  deactivations: 0,
  errors: []
};
```

The runner also records cold boot gzip size (production build), time to first
frame, heap samples, and the count of non-asset JS/TS source lines in the
contender folder.

## Capability checklist (pass/fail, evidence required)

1. WebGPU with WebGL2 fallback.
2. glTF loading with the shared assets.
3. Skeletal animation with blending or a documented equivalent.
4. Cascaded/directional shadows enabled.
5. Vehicle physics (Rapier or Havok) driving the car.
6. Character controller or equivalent for the peds.
7. Positional audio (may be a single engine loop/horn).
8. Streaming hooks: per-cell activation/deactivation.
9. Runs with COOP/COEP headers.
10. Can sit behind `GameContext` without engine-specific types in the game.
11. Pooled/allocation-free hot path, or an acceptable documented substitute.
12. Licence compatible with a commercial browser game.

## Measurement protocol

- One machine, one Chrome build, 1920×1080, DPR 1.
- 5 s warm-up, then 60 s of frames; record p50/p95/max frame intervals.
- Record draw calls, triangles, active instances, activations/deactivations,
  first-frame time, cold boot gzip, and heap samples.
- Run each contender three times; report all runs, not the best one.
- Save a screenshot per contender per backend.
- If a contender cannot run the scene, record the failure and the exact error;
  do not replace it with a different scene.
