E5 - Input-to-canvas latency baseline

Software baseline for G2. Press Run: this tab creates a throwaway room on this dev server, joins it as host and as one controller over the real /ws room flow, and sends 100 press edges about 120 ms apart. For each tap it records the tap time, the frame write, the host receipt of InputFwd, and the next animation frame after the host flash. All stamps use one performance.now() clock.

Not measured here: the phone touch pipeline, Wi-Fi, and display lag. Those need a phone, the TV and a 240 fps camera (see tools/latency-harness/README.md); the JSON marks them PENDING. Display lag is E6 and is never folded into this number. TV probing is deferred.

Nothing is uploaded; the room code, PIN and tokens are never shown or copied. The raw samples are in the latency-harness log format, so node tools/latency-harness/dist/cli.js analyze can re-read a saved copy.
